- (event) Fast path (user asked for autonomous work, questions only for architecture-changing forks). Inputs: PRD prd-noctis-rs-2026-10-19 (79 FR, 10 NFR) + addendum, brief, research/*.
- (decision) Paradigm: hexagonal (ports and adapters) core over an event-driven, lane-based runtime. Ports = Adapter traits; framework logic reaches storage only through ports. Alternatives weighed: plain layered (loses swap-ability the user requires), actor-per-shard (adds message plumbing without benefit).
- (decision) Crate graph: noctis (facade) re-exports noctis-rules, noctis-codec, noctis-ui, noctis-ports, noctis-gateway, noctis-core, noctis-macros, noctis-i18n, noctis-image, noctis-prefix, noctis-testkit; xtask for repo tooling. Users depend only on noctis.
- (decision) Single source of truth for Discord rules: noctis-rules (pure, sync, no I/O) used by proc macros at compile time AND by runtime validators; each rule has a stable id DR-xxx shared with docs/discord-rules.md.
- (decision) Enforcement ladder: compile-time (types, const asserts, proc macros) > App-build (App::build validates the combined Registry before any connection) > runtime (dynamic data only).
- (decision) custom_id is ASCII-only so length in bytes == chars counted by Discord; format: version char + route id + ':' + payload fields (base62/escaped), Ref = '~' + 11 base62 chars (>=64 bits CSPRNG).
- (decision) Payload trait carries const MAX_ENCODED_LEN: Option<usize>; derive(Route) emits a const assert so a Route that can exceed 100 chars fails to compile unless marked by_ref or overflow=spill.
- (decision) Ports are dyn-compatible: methods return BoxFuture (one small alloc per call, negligible vs I/O) so App stays non-generic and Adapters swap at runtime; hot paths (inline payload decode, dispatch) never call ports. Alternative (generic App<R,S,..>) rejected: type explosion for users.
- (decision) Port values are bytes (postcard-serialized by a typed wrapper); keys namespaced {app}:{port}:{key}.
- (decision) Registry is built once by App::build from Module descriptors (data, not side effects) into an immutable O(1) index; module enable/disable is a bitset/ModuleStateStore lookup at dispatch; index swap via arc-swap.
- (decision) Runtime: one tokio task per shard reads the gateway; events go to an interaction lane (priority, never dropped, exempt from backpressure) and a bounded event lane; a semaphore-bounded worker set runs handlers; CPU-heavy work goes to the render pool or spawn_blocking.
- (decision) Responder state machine (Unacked -> Deferred -> Responded/Edited) owns every interaction reply: modal-first rule, V2 flag on every send/edit, ephemerality fixed at registration, auto-defer timer.
- (decision) Noctis owns its Components V2 model (serde, serialized straight to Discord JSON via twilight-http raw request bodies) because twilight 0.17.1 lacks Radio/Checkbox and drops unknown types; twilight-model used for ids, interactions, events.
- (decision) Errors: thiserror enum per crate, facade noctis::Error #[non_exhaustive]; handlers return Result<_, noctis::HandlerError> with an optional user-facing localized message; every handler task wrapped with catch_unwind -> error sink.
- (decision) Images: noctis-image wraps takumi; tw!/view! proc macros validate literal classes with takumi's own Rust tw parser (no Tailwind CLI/Node); dedicated rayon pool + bounded queue; RenderCache key = blake3(template id, template version, postcard(data), size, format).
- (decision) i18n: i18n! proc macro compiles locale files into typed accessors at compile time; LocaleSource port for runtime overrides; command localization read from the same files.
- (decision) Project template sync: xtask public-api snapshot (cargo public-api) + skill coverage check fail CI when the public API changes without updating examples/project-template/.claude/skills/noctis.
- (version) Pinned 2026-10-19 (crates.io): rust 1.91 MSRV ed2024, tokio 1.53, twilight-* 0.17.1, takumi 2.17.0, arc-swap 1.9, postcard 1.1, serde 1.0, thiserror 2.0, tracing 0.1.44, metrics 0.24, rayon 1.12, blake3 1.8, moka 0.12, syn 3.0, quote 1.0, trybuild 1.0, insta 1.49, proptest 1.12.

Ordered handlers run per-guild in order via guild-keyed sub-queues; others run concurrently.
