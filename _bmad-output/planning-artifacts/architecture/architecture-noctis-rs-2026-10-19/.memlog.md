- (decision) Enforcement ladder: compile-time (types, const asserts, proc macros) > App-build (App::build validates the combined Registry before any connection) > runtime (dynamic data only).
- (decision) custom_id is ASCII-only so length in bytes == chars counted by Discord; format: version char + route id + ':' + payload fields (base62/escaped), Ref = '~' + 11 base62 chars (>=64 bits CSPRNG).
- (decision) Payload trait carries const MAX_ENCODED_LEN: Option<usize>; derive(Route) emits a const assert so a Route that can exceed 100 chars fails to compile unless marked by_ref or overflow=spill.
- (decision) Ports are dyn-compatible: methods return BoxFuture (one small alloc per call, negligible vs I/O) so App stays non-generic and Adapters swap at runtime; hot paths (inline payload decode, dispatch) never call ports. Alternative (generic App<R,S,..>) rejected: type explosion for users.
- (decision) Port values are bytes (postcard-serialized by a typed wrapper); keys namespaced {app}:{port}:{key}.
- (decision) Registry is built once by App::build from Module descriptors (data, not side effects) into an immutable O(1) index; module enable/disable is a bitset/ModuleStateStore lookup at dispatch; index swap via arc-swap.
- (decision) Runtime: one tokio task per shard reads the gateway; events go to an interaction lane (priority, never dropped, exempt from backpressure) and a bounded event lane; a semaphore-bounded worker set runs handlers; CPU-heavy work goes to the render pool or spawn_blocking.
- (decision) Responder state machine (Unacked -> Deferred -> Responded/Edited) owns every interaction reply: modal-first rule, V2 flag on every send/edit, ephemerality fixed at registration, auto-defer timer.
