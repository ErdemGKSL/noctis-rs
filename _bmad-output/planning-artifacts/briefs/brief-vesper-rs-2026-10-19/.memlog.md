- (event) User chose autonomous fast path: minimal questions, [ASSUMPTION] tags where inferred; vision taken from the user's chat brief (2026-10-19).
- (decision) Vesper is a Rust Discord bot framework (library), not a skill; built on twilight-rs with tokio, multi-threaded, sharding built in, following twilight's recommended gateway structure.
- (decision) Developer experience modeled on tescord (successor of @mostfeatured/dbi, used by schwi-v2): space-separated command names auto-split into command/group/subcommand and auto-published; replicate features, not exact output.
- (decision) Components V2 is the primary interactive UI; slash commands are bootstrap entry points (e.g. '/setup start' with no params sends a large container with navigation).
- (decision) Built-in UI patterns: step/progress wizards for setup flows, navbar/tab buttons swapping container content when content does not fit, pagination when component limits are exceeded; every V2 limit validated by the framework.
- (decision) Never one listener per component instance: one global handler per component id; custom_id = base id + separator + inline data, or a reference id into a store when data is large.
- (decision) Pluggable adapter traits everywhere (pattern for the whole project): e.g. reference store with read/write trait; framework ships an in-memory impl, users impl the trait for their own DB and pass their struct in.
- (decision) Built-in image and GIF generation using takumi with Tailwind CSS support for dynamic read-only visuals; images are the read-only surface, Components V2 the interactive surface.
- (decision) Design target: bots serving millions of users/guilds; memory allocation kept small (compact custom-id encoding, bounded stores, allocation-aware algorithms).
- (assumption) Open-source library crate(s) intended for crates.io, dual MIT/Apache-2.0 license, first consumer is the user's own bots (schwi successor).
- (assumption) Latest stable Rust, edition 2024; tokio is the only supported runtime.
- (event) Research subagents launched: tescord/dbi features, twilight-rs, Components V2 limits, takumi; findings feed PRD/architecture via research/ folder.
- (event) Finalize: memlog audit done (all decisions in brief, UI doctrine/adapter/platform detail in addendum); structure+prose review applied; brief set final.
