# Localization (i18n)

Covers: locale files, `i18n!`, typed strings and `MessageKey`s, command localization
keys, word-by-word command names, Module-scoped catalogs, `noctis.*` framework strings,
locale resolution, runtime overlays. FR-41..43, FR-72; LOC-01..06; AD-16.

## 1. Files

```text
locales/
  en.yaml     # default locale: every key used in code must exist here
  tr.yaml     # other locales: missing keys fall back to en with a build warning
```

- File names are Discord locale codes (`tr`, `de`, `pt-BR`, `es-419`, `zh-CN`, …) or a
  base language (`en`, `es`, `pt`, `zh`) that covers its variants (`en` →
  `en-US`, `en-GB`) unless a variant file exists (variant overrides base). Unknown names
  are compile errors (LOC-01, 32 Discord locales).
- YAML maps nest; a leaf's key is its dotted path (`setup.step.channel`).
- Placeholders: `{name}`. Every occurrence is replaced.

## 2. Compiling them

```rust
// src/strings.rs
noctis::i18n!(default = "en", dir = "locales");
```

Generates in that module [planned shape]:

| Item | Use |
| --- | --- |
| `Strings::of(locale) -> Strings` | accessor; nested fields mirror the YAML, leaves are methods |
| `s.setup.summary(channel, role) -> String` | args in order of first appearance, each `impl Display` |
| `keys::SETUP_NEED_CHANNEL: MessageKey` | one const per key (dots → `_`, uppercased) |
| `catalog() -> Catalog` | register with `AppBuilder::locales(..)` or `Module::locales(..)` |

A missing key in the default locale, or wrong arguments, is a **compile error**.
`MessageKey` is what `HandlerError::user(key)`, `Flow::Stop(Some(key))`, Wizard
`require` messages and notices take.

## 3. Using strings

```rust
// In Views: the View's locale (User Locale if ephemeral, Guild Locale if public).
let s = Strings::of(cx.locale());
Text::new(s.dashboard.title(escape_markdown(&self.guild_name)))

// In handlers:
let s = Strings::of(ctx.user_locale());      // single-user, ephemeral UI
let s = Strings::of(ctx.guild_locale());     // content many people see
let s = Strings::of(ctx.response_locale());  // whatever this response will be
```

**Rule (from tescord practice):** User Locale for ephemeral single-user UI, Guild
Locale for shared content. Images are content too: format their text in the handler
with the response locale and pass it as Template data.

Choice enums: `#[derive(Choices)] #[choices(key = "profile.pronouns")]` reads labels
from `profile.pronouns.<value>`; `value.label(locale)` returns the text.

## 4. Command localization keys (fixed layout)

```yaml
cmd:
  setup start:                 # the Command Path, words separated by spaces
    desc: Configure the bot …  # CMD-04: 1–100 chars; required in the default locale
  profile:
    desc: Show a member's profile card
    opt:
      user:
        name: user             # option name (CMD-01..03 apply)
        desc: Whose profile …
        choice:
          low: Low             # choice name for value "low" (OPT-09)
cmdword:                       # word-by-word translation of command names
  setup: kurulum
  start: başlat
ctxcmd:
  show_profile:                # key = "show_profile" on #[user_command]
    name: Profili göster       # whole name, 1–32 chars (CTX-01)
```

- `cmd.<path>.name` overrides the word-by-word result for that path.
- Base and group descriptions: `cmd.<base>.desc`, `cmd.<base> <group>.desc`.
- Translated names follow the same rules (CMD-01..03 per word, LOC-02); localized
  option names must be unique per command and locale (LOC-03); the longest
  localization per field counts toward the 8000 budget (LOC-05, CMD-05).
- Default-locale names are checked by `#[command]` at compile time; merged and other
  locales at App build. Publish JSON is generated only from the merged catalog.
- Dispatch always uses default names (LOC-06).

## 5. Module-scoped catalogs (FR-72)

A Module can ship its own catalog: `Module::new("billing").locales(billing::strings::catalog())`
(the `i18n!` call lives in that Module's code with its own `dir`). Catalogs merge per
language at App build; a key defined by two Modules fails with an error naming both.
Disabling a Module never removes strings other Modules use.

## 6. Framework strings (`noctis.*`)

Widgets and notices use keys under the reserved `noctis.` namespace, with built-in
defaults in many languages. Override any of them by defining the key in your files:

| Key | Used for |
| --- | --- |
| `noctis.expired` | default Expired Handler notice |
| `noctis.stale` | Stale Payload notice |
| `noctis.disabled_here` | Module disabled in this guild |
| `noctis.rate_limited` | rate-limit notice (`{retry}` = relative timestamp) |
| `noctis.guard.owner` / `noctis.guard.permissions` | Route Guard failures |
| `noctis.error.generic` | default user-facing error |
| `noctis.wizard.progress` | "Step {step} of {total}: {title}" |
| `noctis.wizard.next` / `back` / `cancel` / `cancelled` | Wizard controls and cancelled state |
| `noctis.pager.first` / `prev` / `next` / `last` / `indicator` / `jump` | Paginator controls ("{page} / {pages}") |
| `noctis.view.outdated` | state-version notice |
| `noctis.render.busy` | render queue full |

Don't invent new `noctis.*` keys; your own keys go elsewhere.

## 7. Resolution (FR-43)

- Interactions: User Locale → Guild Locale → default. Guild events: Guild Locale →
  default. A regional code without its own file falls back to its base language first
  (`pt-BR` → `pt` → default).
- Override per guild with a `LocaleResolver` on the App (runs in pipeline stage 4) or
  in before-Middleware (`ctx.set_locale(Locale::Tr)`), e.g. from a per-guild setting.

## 8. Runtime overlays

A `LocaleSource` Adapter can overlay **content** keys at startup (e.g. strings edited
by a translator in a database). Overlaying `cmd.*`, `cmdword.*` or `ctxcmd.*` is
rejected (published names never change at runtime). Overlay values are checked
against the compiled placeholder set when loaded.
