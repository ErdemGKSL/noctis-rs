# Localization (i18n)

Covers: locale files, `i18n!`, typed strings and `MessageKey`s, command localization
keys, word-by-word command names, Module-scoped catalogs, `noctis.*` framework strings,
locale resolution, runtime overlays. FR-41..43, FR-72; LOC-01..06; AD-16.

## 1. Files

```text
locales/
  en-US.yaml  # default locale: defines every content key, with its placeholders
  tr.yaml     # other locales: a missing key is a build warning and falls back
```

- File names are exactly Discord locale codes (`en-US`, `en-GB`, `tr`, `de`, `pt-BR`,
  `es-ES`, `es-419`, `zh-CN`, …; 32 in all), with the extension `.yaml`. Any other stem,
  including a bare language such as `en.yaml`, wrong case (`EN-us.yaml`) or `en_US.yaml`,
  is a `[LOC-01]` compile error whose help names the matching codes (``help: name it
  `en-GB.yaml` or `en-US.yaml` ``); a `.yml` or `.YAML` file is a `[LOC-01]` error too.
  Subdirectories and other files (`README.md`, `.gitkeep`) are ignored.
- In code, `noctis::rules::Locale` has one variant per code, named after it
  (`Locale::EnUs` = `en-US`, `Locale::Es419` = `es-419`, `Locale::Tr` = `tr`).
  `"en-US".parse::<Locale>()` is exact and case-sensitive: a bare `en`, `en-us` or
  `en_US` does not parse, and the `[LOC-01]` error lists the matching codes. See
  `limits-cheatsheet.md` §Rules types.
- Siblings: `en-US` ↔ `en-GB` and `es-ES` ↔ `es-419`. A file for one also serves the
  other at Publish and at runtime unless the other has its own file. No other code
  has a sibling (`pt-BR`, `zh-TW`, … fall back to the default locale's file).
- A file is UTF-8 (a BOM is fine) holding one YAML document: a map of maps whose leaves
  are strings. A leaf's key is its dotted path (`setup.step.channel`). Quote numbers and
  booleans (`n: "3"`); null leaves, lists, aliases (`*x`), empty maps (`a: {}`) and
  duplicate keys are compile errors naming the file and key. An empty file is an empty map.
- Content key segments are lowercase snake_case (`[a-z][a-z0-9_]*`): never dots inside a
  segment (nest maps), `-`, capitals or a leading digit or `_`. A Rust keyword is fine
  (`type:` becomes the accessor `r#type()`), but `self`, `super` and `crate` are errors,
  and a root-level leaf cannot be named `of` (it is `Strings::of`).
- Placeholders: `{name}` (`[a-z][a-z0-9_]*`) or positional `{0}`, `{1}`, … (no gaps, no
  leading zeros), never both in one value. Every occurrence is replaced; `{}`, `{a b}` and
  an unclosed `{x` are literal text, and there is no brace escaping (`{{n}}` renders
  `{` + n + `}`). A translation must use the same set of placeholders as the default
  value (in any order); a key the default file lacks is an error ("not in the default
  locale").

## 2. Compiling them

```rust
// src/strings.rs
noctis::i18n!(default = "en-US", dir = "locales");   // both optional; these are the defaults
```

Needs the `i18n` cargo feature (`noctis = { features = ["i18n"] }`). Both arguments are
optional and may come in any order; `dir` is relative to the crate root. Every file read
is `include_bytes!`-ed, so editing a locale file rebuilds the crate; a newly added file
is picked up on the next rebuild (touch `src/strings.rs` if nothing else changed).

Generates in that module:

| Item | Use |
| --- | --- |
| `pub struct Strings` (`Clone + Copy + Debug`) | `Strings::of(locale: Locale) -> Strings`; fields are the root maps (nested node structs), methods the root leaves |
| `s.common.refresh() -> &'static str` | a leaf without placeholders |
| `s.setup.progress(n, total, title) -> String` | one `impl Display` per distinct `{name}`, in order of first appearance |
| `s.x.ratio(arg0, arg1) -> String` | positional `{0}`, `{1}`: parameters `arg0`, `arg1`, … in index order |
| `keys::SETUP_NEED_CHANNEL: MessageKey` | one const per content key (dots → `_`, uppercased); two keys mapping to one name (`a.b_c`, `a_b.c`) are a compile error |
| `catalog() -> noctis::i18n::Catalog` | register with `AppBuilder::locales(strings::catalog())` |

`Strings::of(locale)` picks `locale`'s file, else its sibling's, else the default's; a key
that file lacks takes the sibling file's value, else the default value. Both return types
convert into `Text` (`impl Into<Text>`), so they go straight into components.

Checked at `cargo check`:

- a key missing in the default locale (`s.shop.missing()`, `keys::SHOP_MISSING`) or a call
  with the wrong arguments (count or a non-`Display` type) is a rustc compile error
  (LOC-04, by construction);
- a content key missing in another locale file is **one build warning per file**,
  ``[LOC-04] `locales/tr.yaml` lacks 2 key(s) of the default locale `en-US.yaml`:
  `a`, `b`; they fall back at runtime``, raised through the `deprecated` lint (up to 10
  keys, then `, and N more`). Silence it with `#![allow(deprecated)]` on the module that
  calls `i18n!`, or make it an error with `#![deny(deprecated)]`.

`MessageKey` is what `HandlerError::user(key)`, `HandlerError::with_message(key)`,
`Flow::Stop(Some(key))`, `ctx.reply_text(key)`, `defaults(label = keys::X)` and every
override take. `MessageKey` and the `Translate` trait live in `noctis::rules`
(`MessageKey::new("setup.step.channel")` is a `const fn`; keys under `noctis.` are
reserved for the framework).

`Catalog` (`noctis::i18n::Catalog`, `Clone + Copy + Debug`) is the compiled files of one
`i18n!`: `origin()` (`"<crate>/<dir>"`), `default_locale()`, `locales()` (the locales that
have a file), `get(locale, key)` (that file only, no fallback), `keys()` (every key of
every file, sorted, deduplicated, `cmd.*` and `noctis.*` included) and
`placeholders(key)` (content and `noctis.*` keys; positional names are `"0"`, `"1"`, …).
It implements `Translate` (locale → sibling → default, then `noctis::i18n::format`).
`noctis::i18n::format(template, &[("n", &3 as &dyn Display)])` is the substitution the
accessors use.

Registering: `AppBuilder::locales(catalog)` (repeat it for several catalogs; the same
catalog twice counts once), or `Module::locales(catalog)` for a Module's own catalog
(§5). A key that two catalogs define fails `build()` with
`BuildViolation::DuplicateLocaleKey { key, first, second, first_owner, second_owner }`
(`first`/`second` are origins, the owners are `LocaleOwner::App` or
`LocaleOwner::Module(id)`), shown as ``locale key `shop.title` is defined by two
catalogs: `bot/locales` (AppBuilder::locales) and `shop/locales` (Module `shop`)``,
collected with the other violations before any connection. Every `Text::Key`,
`defaults(..)` key, notice and `noctis.*` override then resolves from the catalogs, and
keys no catalog has fall back to the built-in `noctis.*` texts. Without any `.locales(..)`
only the built-in strings exist.

## 3. Using strings

```rust
// For a render function: the response's locale (User Locale if ephemeral, Guild
// Locale if public), passed in as `&Strings`.
let s = Strings::of(ctx.response_locale());
ctx.update(render_dashboard(&data, &s, tab, page, ctx.limits())).await
// inside render_dashboard(d, s, ..):
TextDisplay::new(s.dashboard.title(escape_markdown(&d.guild_name)))

// In handlers:
let s = Strings::of(ctx.user_locale());      // single-user, ephemeral UI
let s = Strings::of(ctx.guild_locale());     // content many people see
let s = Strings::of(ctx.response_locale());  // whatever this response will be
```

`ctx.user_locale()`, `ctx.guild_locale()` and `ctx.response_locale()` return a
resolved `noctis::rules::Locale` (never an `Option`, never a raw string): pass them
straight to `Strings::of`. How they are resolved is §7. A bot without locale files
sees `Locale::EnUs` everywhere.

**Rule (from tescord practice):** User Locale for ephemeral single-user UI, Guild
Locale for shared content. Images are content too: format their text in the handler
with the response locale and pass it as Template data.

Component and modal texts: a `keys::` path in `defaults(..)` (`label`, `placeholder`,
`title`) is a locale key the Responder resolves in the response locale (a modal title in
the User Locale first) and validates after resolving (Strict: `ResponderError::Invalid`;
Lenient: truncated with `…`); a string literal there is fixed text checked at
`cargo check`. Input attribute texts (`#[text_input("Bio", placeholder = "…")]`,
`#[radio_group(..)]`, …) are literals only; localize them per render with
`.overrides(XOverrides { bio: InputOverrides { label: Some(keys::X.into()), .. }, .. })`.
`Choices` labels are literal text; localized choice labels are [planned].

## 4. Command localization keys (fixed layout)

```yaml
cmd:
  setup:                       # the Command Path's words as nested maps: cmd.setup.start
    description: Set up …      # base /setup description (FR-57)
    start:
      description: Configure the bot …  # CMD-04: 1–100 chars; required in the default locale
  profile:
    description: Show a member's profile card
    opt:
      user:
        name: user             # option name (CMD-01..03 apply)
        description: Whose profile …
        choice:
          low: Low             # choice name for value "low" (OPT-09)
cmdword:                       # word-by-word translation of command names
  setup: kurulum
  start: başlat
ctxcmd:
  show_profile:                # key = "show_profile" on #[user_command]
    name: Profili göster       # whole name, 1–32 chars (CTX-01)
```

- `<path>` is the Command Path's words joined by `.` (nested YAML maps). A Command
  word named `name`, `description` or `opt` would be ambiguous and is a compile error
  with the `i18n` feature.
- `cmd.<path>.name` overrides the word-by-word result for that path.
- Base and group descriptions: `cmd.<base>.description`, `cmd.<base>.<group>.description`.
- `cmd.*`, `cmdword.*` and `ctxcmd.*` keys get no typed accessors; only `#[command]`
  and Publish read them.
- Translated names follow the same rules (CMD-01..03 per word, LOC-02); localized
  option names must be unique per command and locale (LOC-03); the longest
  localization per field counts toward the 8000 budget (LOC-05, CMD-05).
- With the `i18n` feature, `#[command]` reads the default-locale file at compile
  time: `cmd.<path>.description` is the description (a `description = "…"` literal may be
  omitted; one that differs from the file is a compile error), and default-locale names
  are checked there. A Module whose `i18n!` uses another `dir` passes it with
  `#[command(.., locales = "<dir>")]`. Merged and other locales are checked at App
  build. Publish JSON is generated only from the merged catalog.
- Dispatch always uses default names (LOC-06).

## 5. Module-scoped catalogs (FR-72)

A Module can ship its own catalog with
`pub fn locales(self, catalog: noctis::i18n::Catalog) -> Module` (`#[must_use]`, repeatable).
The `i18n!` call lives in that Module's code with its own `dir`:

```rust
// billing/src/lib.rs (a Module shipped as its own crate)
mod strings {
    noctis::i18n!(dir = "locales");   // billing/locales/en-US.yaml, tr.yaml
}

pub fn module() -> noctis::Module {
    noctis::Module::new("billing")
        .add::<Invoice>()
        .locales(strings::catalog())
}
```

- Merge order at `App::build`: the App's catalogs (`AppBuilder::locales`, in call order,
  whatever the order of `.locales` and `.module` calls), then every mounted Module's in
  fold order (roots in mount order, each parent before its children, each Module's
  catalogs in call order). A Module with catalogs but no handlers still contributes them.
- Catalogs with one `origin()` (`"<crate>/<dir>"`) count once: the same catalog in two
  Modules, or in the App and a Module, is no clash; its owner is the first that added it.
- A key two different catalogs define (even with identical text, `noctis.*` and
  `cmdword.*` included) is one `DuplicateLocaleKey` per key, naming both origins and both
  owners (``Module `shop` `` or `AppBuilder::locales`), in merge order, then key order.
- Strings are App-wide: a key resolves by key alone, so any Module's handler can send
  another Module's `keys::X` (`ctx.reply_text(shop::strings::keys::SHOP_TITLE)`), each
  catalog keeps its own default-locale fallback chain, and a Module's `noctis.*` override
  applies to every Module. Disabling a Module never removes its strings.
- A single-crate bot keeps one App-level catalog; `Module::locales` is for Modules
  shipped as their own crates or with their own `dir`.

## 6. Framework strings (`noctis.*`)

Built-in notices use keys under the reserved `noctis.` namespace, with built-in
English defaults that every locale falls back to. Override one by defining the key in
any of your locale files (it need not be in the default file); the override must use
exactly the listed placeholders, and any other `noctis.*` key is a compile error
(`` `noctis.` is reserved: use your own namespace ``). Overrides get no accessor and no
`keys::` const. A locale whose chain (locale, sibling, default file) has no override
shows the built-in text.

```yaml
# locales/tr.yaml
noctis:
  expired: Bu panelin süresi doldu. Komutu yeniden çalıştır.
  rate_limited: "Çok sık yapıyorsun. {retry} tekrar dene."   # must keep {retry}
```

| Key | Used for | Default (en-US) |
| --- | --- | --- |
| `noctis.error.generic` | default user-facing error, every panic | Something went wrong. Please try again later. |
| `noctis.validation.failed` | an option failed to decode or validate | That input isn't valid. Check it and try again. |
| `noctis.expired` | default Expired Handler notice | This interaction has expired. Run the command again. |
| `noctis.stale` | reserved; v1 sends `noctis.expired` for stale ids too | This message is out of date. Run the command again. |
| `noctis.disabled_here` | Module disabled in this guild | This feature is disabled here. |
| `noctis.rate_limited` | rate-limit notice (`{retry}` = relative timestamp) | You're doing that too often. Try again {retry}. |
| `noctis.guard.failed` | a custom Route Guard returned `Access::deny()` | You can't use this. |
| `noctis.guard.owner` | the `owner = field` Route Guard: not the user in the field | Only the person who started this can use it. |
| `noctis.guard.permissions` | the `permissions = …` Route Guard: missing permissions, or a DM | You don't have permission to use this. |
| `noctis.render.busy` [planned] | render queue full | |

Don't invent new `noctis.*` keys; your own keys go elsewhere. Noctis has no UI widgets,
so labels such as "Next", "Back", "Cancel" and "Page 2 of 7" are your own keys (the
template uses `common.next`, `setup.back`, `dashboard.page`). A notice whose key no
registered catalog defines shows the `noctis.error.generic` text and logs `warn` "missing
message key" (target `noctis::i18n`, field `key`); a component `Text::Key` no catalog has
is sent as the key itself, with the same warning.

## 7. Resolution (FR-43)

**Rule: User Locale for ephemeral single-user UI, Guild Locale for shared content.**
`ctx.response_locale()` applies it for you: the User Locale for an ephemeral response
(and under `response = update` on an ephemeral message), the Guild Locale for a public
one.

What the App ships, computed once at `build()` from the merged catalogs (§4):

- **available**: every locale that has a file in *any* catalog (`AppBuilder::locales`
  and every `Module::locales`); `{en-US}` without catalogs;
- **default**: the `default` of the first catalog in merge order (the App's catalogs
  first, then Modules in mount pre-order); `en-US` without catalogs. There is no
  separate default-locale setter.

One step `step(code)` = `code` when it is available, else its `Locale::sibling()` when
that is available (`en-GB` ↔ `en-US`, `es-419` ↔ `es-ES`), else nothing. Raw codes are
parsed exactly: an absent, empty, wrong-case (`en-us`), bare (`en`) or unknown code
counts as absent and the chain moves on, silently.

| Run | `user_locale()` | `guild_locale()` |
| --- | --- | --- |
| interaction (commands, menus, components, modals, Expired Handlers, autocomplete) | `step(locale)` ∥ `step(guild_locale)` ∥ default | `step(guild_locale)` ∥ `step(locale)` ∥ default |
| guild event (`EventCtx::guild_locale()`) | = guild | `step(recorded preferred_locale)` ∥ default |
| `Dispatcher::run_command` | `step(CommandInvocation::locale)` ∥ guild step ∥ default | `step(recorded preferred_locale)` ∥ user step ∥ default |

- The Guild Locale falls back to the User Locale in a DM (no `guild_locale`; a DM has
  one reader), or when the guild's code has no file (nor a sibling file).
- Examples with `en-US.yaml` + `tr.yaml`, `default = "tr"`: an `en-GB` user gets `en-US`
  (sibling); a `pt-BR` user gets `tr` (no sibling, so the guild step, then the default);
  a `tr` user in an `en-US` guild gets user `tr`, guild `en-US`.
- **Events and the guild record.** Gateway events carry no locale, so Noctis keeps one
  bounded per-guild record of `preferred_locale`: `GUILD_CREATE` (available) and
  `GUILD_UPDATE` set it (an unparseable code removes it), `GUILD_DELETE` removes it
  (an outage, `unavailable: true`, keeps it). It needs the `GUILDS` intent, which every
  App requests; whenever an App has at least one event handler, `build()` adds
  `GUILD_CREATE | GUILD_UPDATE | GUILD_DELETE` to the gateway filter. An interaction's
  `guild_locale` refreshes an existing record but never creates one. A guild with no
  record (and a DM) resolves to the default.
- Rendering then follows each catalog's own fallback (locale file → sibling → that
  catalog's default file, LOC-04), so a resolved locale without a file still renders.

### Overriding: `LocaleResolver` and Middleware

```rust
use noctis::{LocaleRequest, Locales};
use noctis::rules::Locale;

// App-wide, sync, no I/O: runs once per run at pipeline stage 4.
builder.locale_resolver(|request: &LocaleRequest| match request.guild_id {
    Some(id) if id.get() == BR_GUILD => Locales { guild: Locale::PtBr, ..request.resolved },
    _ => request.resolved,
});

// Per-guild settings from a store: a before-Middleware (async, may do I/O).
async fn guild_language(ctx: BeforeCtx) -> HandlerResult<Flow> {
    if let Some(guild) = ctx.guild_id() {
        if let Some(code) = ctx.kv().get::<String>(&format!("lang:{guild}")).await? {
            if let Ok(locale) = code.parse::<Locale>() {
                ctx.set_guild_locale(locale);
            }
        }
    }
    Ok(Flow::Continue)
}
```

- `Locales { user: Locale, guild: Locale }` (`Copy`, `Eq`, `Hash`): the run's pair.
- `LocaleRequest` (`#[non_exhaustive]`, `Copy`, read-only): `invocation: Invocation`
  (`Command`, `ContextMenu`, `Component`, `Modal`, `Event`, or `Autocomplete { path }`,
  which only a resolver sees), `guild_id`, `user_id` (`None` for events),
  `discord_user: Option<Locale>` (Discord's `locale`, parsed; `None` when absent or
  unknown, always `None` for events), `discord_guild: Option<Locale>` (`guild_locale`,
  or the guild record for events and the Dispatcher), `resolved: Locales` (the
  built-in resolution above).
- `trait LocaleResolver: Send + Sync + 'static { fn resolve(&self, &LocaleRequest) -> Locales; }`,
  implemented for every `Fn(&LocaleRequest) -> Locales + Send + Sync + 'static`.
  `AppBuilder::locale_resolver(impl LocaleResolver) -> &mut Self`; the last call wins.
  - It runs **exactly once per run**, once the handler is known and before its context
    exists: slash Commands, context menus, components, modal submits, the Expired
    Handler chain, autocomplete, events and `Dispatcher::run_command`.
  - Its value is used **verbatim** (no availability check).
  - It is **sync and must not do I/O**; per-guild lookups go in a before-Middleware.
  - A panic is caught: one `error` on target `noctis::i18n` naming the handler, the run
    keeps the built-in resolution, nothing reaches an Error Sink.
  - Notices sent before the handler is known (a malformed or unknown `custom_id`, a kind
    mismatch, a missing author) use the built-in resolution and never call it.
- Before-Middleware setters on `BeforeCtx`: `set_user_locale(Locale)`,
  `set_guild_locale(Locale)` and `set_locale(Locale)` (both). The last write wins, a
  later Middleware reads earlier writes (`ctx.user_locale()` / `ctx.guild_locale()` on
  `BeforeCtx` and `AfterCtx`), and a call after the before chain ended (from a kept
  clone) is ignored with one `debug` on `noctis::middleware`.
- An override reaches **everything** of the run: the handler's `*_locale()`, every
  Responder send (`Text` keys, also an edit after the auto-defer), `ctx.reply_text(key)`,
  the error, panic, `Flow::Stop(Some(key))` and Guard notices (User Locale), and the
  after-Middleware. Autocomplete runs no Middleware, so only the resolver applies there.
- Webhook sends resolve keys in the App default (no user, no guild).

## 8. Runtime overlays

A `LocaleSource` Adapter can overlay **content** keys at startup (e.g. strings edited
by a translator in a database). Overlaying `cmd.*`, `cmdword.*` or `ctxcmd.*` is
rejected (published names never change at runtime). Overlay values are checked
against the compiled placeholder set when loaded.
