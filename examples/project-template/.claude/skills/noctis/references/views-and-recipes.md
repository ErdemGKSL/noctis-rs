# Views and UI recipes

Covers: what a View is in Noctis (a plain render function), the update flow
(`ctx.respond` / `ctx.update` / `ctx.reply_text`), the budget helpers, attachments,
mentions and user text, select freshness, the UI recipes with complete code (tabs,
pagination, step flow, settings screen), the UI quality rulebook, and the best
practices (and pitfalls) taken from the maintainer's production bot. Doctrine:
UD-1..UD-8. Rules: CV2-*, CID-02, MSG-05, ATT-*.

**Noctis has no UI widgets.** There is no `View` trait, no Navbar, Wizard or Paginator,
no framework-managed UI state, no automatic re-render and no automatic pagination
(withdrawn on 2026-10-20). You write each screen as a function, keep its ids in your own
Route Payloads, and Noctis makes sure every message you build is valid, fits Discord's
limits and is sent with the right response type.

## 1. A View is a plain render function

```rust
/// Pure: loaded data in, message out. No I/O, no `.await`.
pub fn render_x(data: &XData, s: &Strings, selected: Option<u32>, page: u16) -> V2Message
```

- **One render function per screen**, in the feature's `view.rs`. It is the single source
  of truth for that message: the slash Command calls it for the first response and every
  component and modal handler calls it again after changing something. Never build the
  same message in two places.
- **Arguments, in this order:** the data the handler loaded (`&XData`), the strings for
  the response's locale (`&Strings`, from `Strings::of(ctx.response_locale())`), then the
  ids that select what to show (selected entity, tab, page, step), taken from the
  Payload. Add `&Limits` (`ctx.limits()` [planned]) when the function sizes a page with
  the budget helper.
- **Pure and deterministic.** All I/O (database, cache, `ctx.render(..)` for images)
  happens in the handler before the call. The same arguments give the same JSON (except
  per-render select nonces), so tests snapshot the function directly (`testing.md`).
- **Returns `V2Message`** (`components-v2.md` §12). Building is infallible; the
  Responder validates every Limit before the request (FR-24) and a violation is a typed
  error naming the path, never a 400 from Discord.
- **UI state lives only in typed Payload fields** of the feature's own Routes: the
  selected entity id, a tab `#[derive(PayloadEnum)]`, a `page: u16`, a `step` enum. The
  derive proves the `custom_id` fits 100 characters (CID-01); nothing is stored per
  message (UD-7). If the state is large, use a `by_ref` Route (`routes-payloads-refs.md`).

## 2. The update flow

Every handler has the same four steps:

```text
decode the Payload  →  validate / authorize  →  write to storage  →  ctx.update(render_x(..))
(the #[handler] arg)   (Route Guards + checks)   (port, State<T>)      (or ctx.respond / ctx.reply_text)
```

| Call [planned, Story 8.1] | Sends | Use for |
| --- | --- | --- |
| `ctx.respond(msg).await` | a **new** message: the initial response (declared ephemerality), the edit of the deferred original after an auto-defer, or a follow-up once answered | slash Commands, context menus, a component that opens a separate panel |
| `ctx.update(msg).await` | an **edit** of the message the component lives on (type 7, or `edit_original` after the type-6 auto-defer) | every button, select and modal submit that changes the screen (`ComponentCtx`, `ModalSubmitCtx` only) |
| `ctx.reply_text(text).await` | a one-line V2 notice, **ephemeral** by default (`.public()` opts out); a follow-up once answered | "Pick a channel first.", "Saved.", "Not found." (`String`, `&'static str` or a `MessageKey`) |

Each returns `HandlerResult<Responded>`; return it from the handler. Noctis picks the
callback type, adds `IS_COMPONENTS_V2`, applies the declared ephemerality, defers for you
when the handler is slow (FR-21) and validates the message. A second initial response
is `ResponderError::AlreadyResponded`. Use the typestate `Responder` (`responder.md` §4)
only for modals and multi-message replies. Returning a `V2Message` from a Command works
too (it is sent like `ctx.respond`).

### 3.1 Tabs (UD-5)

A tab is a `PayloadEnum` field; the render function `match`es it; the tab row is one
Route button per tab, the active one disabled.

```rust
#[derive(PayloadEnum, Debug, Clone, Copy, PartialEq, Eq)]
pub enum DashTab { Overview, Roles, Modules }        // append variants, never reorder

impl DashTab { pub const ALL: [Self; 3] = [Self::Overview, Self::Roles, Self::Modules]; }

#[derive(Route, Debug, Clone, Copy)]
#[route("dash.tab", permissions = MANAGE_GUILD)]     // runtime argument [planned]
pub struct OpenTab { pub guild: Id<GuildMarker>, pub tab: DashTab }

pub fn render_dashboard(d: &DashData, s: &Strings, tab: DashTab) -> V2Message {
    let tabs = ActionRow::buttons(DashTab::ALL.map(|t| {
        OpenTab { guild: d.guild, tab: t }
            .button()
            .label(match t {
                DashTab::Overview => s.dashboard.tab.overview(),
                DashTab::Roles => s.dashboard.tab.roles(),
                DashTab::Modules => s.dashboard.tab.modules(),
            })
            .style(if t == tab { ButtonStyle::Primary } else { ButtonStyle::Secondary })
            .disabled(t == tab)                       // visible active state
    }));
    let body: Vec<ContainerComponent> = match tab {
        DashTab::Overview => vec![TextDisplay::new(s.dashboard.overview(d.roles.len())).into()],
        DashTab::Roles => d.roles.iter().map(|r| TextDisplay::new(r.clone()).into()).collect(),
        DashTab::Modules => d.modules.iter().map(|m| module_row(d, s, m)).collect(),
    };
    let container = body.into_iter().fold(
        Container::new().push(TextDisplay::new(format!("## {}", s.dashboard.title()))).push(tabs),
        Container::push,
    );
    V2Message::new(Components::new().push(container))
}

#[handler]
async fn open_tab(ctx: ComponentCtx, to: OpenTab, db: State<Db>) -> HandlerResult<Responded> {
    let data = db.dashboard(to.guild).await?;
    ctx.update(render_dashboard(&data, &Strings::of(ctx.response_locale()), to.tab)).await
}
```

- At most 5 tabs (one Action Row, CV2-06; 6 is a compile error). More sections: a String
  Select as the navigation, or split the screen.
- The slash Command calls the same function with `DashTab::Overview`.

### 3.2 Pagination (UD-6)

A `page: u16` field, a slice, prev/next Route buttons disabled at the bounds. Size the
page with the budget helper (§4) against the fixed parts of the message, using a
worst-case row so page boundaries don't move when names get longer.

```rust
/// Prev/next carry the target page. Its own Route keeps the ids distinct from the tab
/// buttons, and prev/next target different pages, so ids are unique (CID-02).
#[derive(Route, Debug, Clone, Copy)]
#[route("dash.page", permissions = MANAGE_GUILD)]
pub struct TurnPage { pub guild: Id<GuildMarker>, pub page: u16 }

const ROW_MAX_CHARS: usize = 230;                     // mention + escaped 100-char name

pub fn render_roles(d: &DashData, s: &Strings, page: u16, limits: &Limits) -> V2Message {
    if d.roles.is_empty() {
        return frame(s, vec![TextDisplay::new(s.dashboard.no_roles()).into()]); // empty state
    }
    let fixed = frame(s, vec![page_line(s, 0, 1).into(), pager(d, s, 0, 1).into()]);
    let per_page = Budget::of(&fixed, limits)        // [planned, Story 8.3]
        .fits(&TextDisplay::new("x".repeat(ROW_MAX_CHARS)))
        .max(1);
    let pages = d.roles.len().div_ceil(per_page);
    let page = usize::from(page).min(pages - 1);      // the page is client input: clamp it
    let mut body: Vec<ContainerComponent> = d.roles[page * per_page..]
        .iter()
        .take(per_page)
        .map(|(mention, name)| TextDisplay::new(format!("{mention} · {}", escape_markdown(name))).into())
        .collect();
    let (page, pages) = (page as u16, pages as u16);  // both ≤ the role count
    body.push(page_line(s, page, pages).into());
    body.push(pager(d, s, page, pages).into());
    frame(s, body)
}

fn pager(d: &DashData, s: &Strings, page: u16, pages: u16) -> ActionRow {
    ActionRow::buttons([
        TurnPage { guild: d.guild, page: page.saturating_sub(1) }
            .button().label(s.common.previous()).disabled(page == 0),
        TurnPage { guild: d.guild, page: page + 1 }
            .button().label(s.common.next()).disabled(page + 1 >= pages),
    ])
}

fn page_line(s: &Strings, page: u16, pages: u16) -> TextDisplay {
    TextDisplay::new(format!("-# {}", s.dashboard.page(page + 1, pages)))  // "Page 2 of 7"
}

fn frame(s: &Strings, body: Vec<ContainerComponent>) -> V2Message {
    let header = Container::new().push(TextDisplay::new(format!("## {}", s.dashboard.title())));
    V2Message::new(Components::new().push(body.into_iter().fold(header, Container::push)))
}

#[handler]
async fn turn_page(ctx: ComponentCtx, to: TurnPage, db: State<Db>) -> HandlerResult<Responded> {
    let data = db.dashboard(to.guild).await?;
    let s = Strings::of(ctx.response_locale());
    ctx.update(render_roles(&data, &s, to.page, ctx.limits())).await
}
```

- Data from a database: query one page plus one row (`LIMIT per_page + 1 OFFSET …`) and
  disable next when the extra row is missing. Checking `rows.len() < per_page` disables
  next one page too late when the last page is exactly full.
- To pick one of many entities instead, use a String Select of at most 25 options per
  page (CV2-09) with the same prev/next row.

### 3.3 Step flow (UD-4)

A `step` field, a "Step n of m: Title" line, Back/Cancel/Next, Next disabled until the
step is valid, and a check in the handler for old or forged clicks.

```rust
#[derive(PayloadEnum, Debug, Clone, Copy, PartialEq, Eq)]
pub enum SetupStep { Channel, Role, Confirm }

/// Back and Next carry the whole state plus the step to show.
#[derive(Route, Debug, Clone, Copy)]
#[route("setup", owner = owner)]                      // only the invoker may click [planned]
pub struct SetupState {
    pub owner: Id<UserMarker>,
    pub step: SetupStep,
    pub log_channel: Option<Id<ChannelMarker>>,
    pub mod_role: Option<Id<RoleMarker>>,
}

#[derive(Route, Debug, Clone, Copy)]
#[route("setup.ch", select, owner = owner)]           // select: fresh defaults on every render
pub struct PickLogChannel { pub owner: Id<UserMarker>, pub mod_role: Option<Id<RoleMarker>> }

#[derive(Route, Debug, Clone, Copy)]
#[route("setup.cancel", owner = owner)]
pub struct CancelSetup { pub owner: Id<UserMarker> }

pub fn render_setup(st: SetupState, s: &Strings) -> V2Message {
    let title = match st.step {
        SetupStep::Channel => s.setup.step.channel(),
        SetupStep::Role => s.setup.step.roles(),
        SetupStep::Confirm => s.setup.step.confirm(),
    };
    let progress = TextDisplay::new(format!("## {}", s.setup.progress(st.step as usize + 1, 3, title)));
    let input: ContainerComponent = match st.step {
        SetupStep::Channel => ActionRow::select(
            PickLogChannel { owner: st.owner, mod_role: st.mod_role }
                .channel_select()
                .default_channels(st.log_channel),    // pre-filled with the current value
        ).into(),
        SetupStep::Role => ActionRow::select(
            PickModRole { owner: st.owner, log_channel: st.log_channel }
                .role_select()
                .default_roles(st.mod_role),
        ).into(),
        SetupStep::Confirm => TextDisplay::new(summary(s, st)).into(),
    };
    let cancel = Button::from(CancelSetup { owner: st.owner }.button().label(s.setup.cancel()));
    let next = |step, ok: bool| Button::from(
        SetupState { step, ..st }.button().label(s.setup.next())
            .style(ButtonStyle::Primary).disabled(!ok),
    );
    let back = |step| Button::from(SetupState { step, ..st }.button().label(s.setup.back()));
    let nav = match st.step {
        SetupStep::Channel => ActionRow::buttons([cancel, next(SetupStep::Role, st.log_channel.is_some())]),
        SetupStep::Role => ActionRow::buttons([back(SetupStep::Channel), cancel, next(SetupStep::Confirm, st.mod_role.is_some())]),
        SetupStep::Confirm => ActionRow::buttons([back(SetupStep::Role), cancel, finish_button(st, s)]),
    };
    let c = Container::new().push(progress).push(input).push(Separator::small()).push(nav);
    V2Message::new(Components::new().push(c))
}

/// Back and Next. The button was disabled while invalid, but Payloads are client input.
#[handler]
async fn go_to_step(ctx: ComponentCtx, st: SetupState) -> HandlerResult<Responded> {
    if st.step != SetupStep::Channel && st.log_channel.is_none() {
        return ctx.reply_text(keys::SETUP_NEED_CHANNEL).await;   // ephemeral one-liner
    }
    ctx.update(render_setup(st, &Strings::of(ctx.response_locale()))).await
}

#[handler]
async fn pick_log_channel(ctx: ComponentCtx, p: PickLogChannel) -> HandlerResult<Responded> {
    let st = SetupState {
        owner: p.owner,
        step: SetupStep::Channel,                     // stay; the user presses Next
        log_channel: ctx.values().channels().first().copied(),
        mod_role: p.mod_role,
    };
    ctx.update(render_setup(st, &Strings::of(ctx.response_locale()))).await
}

#[handler]
async fn cancel_setup(ctx: ComponentCtx, _c: CancelSetup) -> HandlerResult<Responded> {
    // Same message, no components left (a way out on every step).
    let s = Strings::of(ctx.response_locale());
    ctx.update(V2Message::new(Components::new().push(TextDisplay::new(s.setup.cancelled())))).await
}
```

- Progress is "Step n of m: Title", never "page 2 of 3".
- The Finish button exists only when every value is set; make its Route's fields
  non-`Option` so the type proves the configuration is complete.
- Free text in a step: a button opens a modal whose submit Route carries the same state;
  its handler validates and calls `ctx.update(render_setup(next_state, &s))`. Never chain
  modal → modal: go back to a message step first (`modals.md` §5).
- State too large for 100 characters: make the state Route `overflow = spill` (by Ref
  when it does not fit, with a TTL); an expired Ref reaches your `on_expired` handler,
  which can call `render_setup` for step 1 plus a `reply_text` notice.

### 3.4 Settings screen (re-editable config, schwi-style)

One Container per screen: an entity switcher, settings as Sections with an accessory
button, pre-filled selects, toggles, add and delete rows, and a button → modal →
re-render chain. This is a complete "ticket systems" feature.

```rust
// ---- mod.rs: Routes. Every one carries the id of the system being edited. ---------
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.pick", select)]
pub struct PickSystem;                                // the chosen id arrives in ctx.values()
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.text", opens_modal)]
pub struct EditText { pub system: u32 }
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.text.save")]
pub struct SaveText { pub system: u32 }              // same Payload as EditText
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.roles", select)]
pub struct SetRoles { pub system: u32 }
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.toggle")]
pub struct ToggleSystem { pub system: u32, pub enable: bool }  // the action, not the state
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.add")]
pub struct AddSystem;
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.del")]
pub struct AskDelete { pub system: u32 }
#[derive(Route, Debug, Clone, Copy)] #[route("ticket.del.ok", by_ref, one_shot, ttl = "15m")]
pub struct ConfirmDelete { pub system: u32 }

#[derive(Modal, Debug)]
#[modal(route = SaveText, title = "Button text")]
pub struct TextForm {
    #[text_input("Text", max_length = 80)]
    pub text: Option<String>,
}

// ---- view.rs ------------------------------------------------------------------------
pub struct TicketData { pub systems: Vec<TicketSystem> }   // ≤ 25, loaded by the handler

pub fn render_ticket_setup(d: &TicketData, s: &Strings, selected: Option<u32>) -> V2Message {
    let mut c = Container::new().push(TextDisplay::new(format!("# {}", s.ticket.title())));
    let current = selected
        .and_then(|id| d.systems.iter().find(|t| t.id == id))
        .or(d.systems.first());

    // Entity switcher, only when there is something to switch between.
    if d.systems.len() > 1 {
        c = c.push(ActionRow::select(PickSystem.string_select(d.systems.iter().map(|t| {
            SelectOption::new(s.ticket.system_label(t.id), t.id.to_string())
                .default(Some(t.id) == current.map(|c| c.id))
        }))));
    }

    if let Some(t) = current {
        // Scalar setting: value as text, "Edit" as the accessory (Primary when unset).
        let text = t.button_text.as_deref().map_or_else(|| s.common.unset(), escape_markdown);
        c = c
            .push(Separator::small())
            .push(Section::new(
                [TextDisplay::new(format!("**{}**\n-# {text}", s.ticket.button_text()))],
                EditText { system: t.id }.button().label(s.common.edit()).style(
                    if t.button_text.is_some() { ButtonStyle::Secondary } else { ButtonStyle::Primary },
                ),
            ))
            // Multi-value setting: a caption plus a select pre-filled with the current roles.
            .push(TextDisplay::new(s.ticket.responsible_roles()))
            .push(ActionRow::select(
                SetRoles { system: t.id }.role_select().max_values(25).default_roles(t.roles.iter().copied()),
            ))
            // Toggle: state in the text, action in the button (Success enables, Danger disables).
            .push(Section::new(
                [TextDisplay::new(format!("**{}** · {}", s.ticket.enabled(),
                    if t.enabled { s.common.enabled() } else { s.common.disabled() }))],
                ToggleSystem { system: t.id, enable: !t.enabled }.button()
                    .label(if t.enabled { s.common.disable() } else { s.common.enable() })
                    .style(if t.enabled { ButtonStyle::Danger } else { ButtonStyle::Success }),
            ))
            .push(Separator::large())
            .push(Section::new([TextDisplay::new(s.ticket.delete())],
                AskDelete { system: t.id }.button().label(s.common.delete()).style(ButtonStyle::Danger)));
    } else {
        c = c.push(TextDisplay::new(format!("-# {}", s.ticket.none_yet())));   // empty state
    }
    if d.systems.len() < 25 {                         // the switcher holds at most 25 options
        c = c.push(Section::new([TextDisplay::new(s.ticket.add())],
            AddSystem.button().label(s.common.add()).style(ButtonStyle::Primary)));
    }
    V2Message::new(Components::new().push(c))
}

// ---- handlers.rs ----------------------------------------------------------------------
#[command("ticket setup", description = "Set up ticket systems", ephemeral,
          permissions = ADMINISTRATOR, contexts = [Guild])]
async fn ticket_setup(ctx: CommandCtx, db: State<Db>) -> HandlerResult<Responded> {
    let guild = ctx.guild_id().ok_or_else(|| HandlerError::user(keys::COMMON_GUILD_ONLY))?;
    let data = db.ticket_systems(guild, 25).await?;
    ctx.respond(render_ticket_setup(&data, &Strings::of(ctx.response_locale()), None)).await
}

#[handler]
async fn pick_system(ctx: ComponentCtx, _p: PickSystem, db: State<Db>) -> HandlerResult<Responded> {
    // Select values are client input: parse, never cast.
    let Some(id) = ctx.values().strings().first().and_then(|v| v.parse::<u32>().ok()) else {
        return ctx.reply_text(keys::TICKET_NOT_FOUND).await;
    };
    redraw(&ctx, &db, Some(id)).await
}

/// Button → modal: the modal Route gets the same Payload, pre-filled with the stored value.
#[handler]
async fn edit_text(ctx: ComponentCtx, e: EditText, r: ComponentResponder<OpensModal>, db: State<Db>)
    -> HandlerResult<Responded>
{
    let current = db.ticket_system(e.system).await?.and_then(|t| t.button_text);
    Ok(r.modal(TextForm::modal(SaveText { system: e.system }).text(current)).await?.done())
}

/// Modal → re-render the message the button was on.
#[handler]
async fn save_text(ctx: ModalSubmitCtx, save: SaveText, form: TextForm, db: State<Db>)
    -> HandlerResult<Responded>
{
    let guild = ctx.guild_id().ok_or_else(|| HandlerError::user(keys::COMMON_GUILD_ONLY))?;
    // Authorize: the id came from the client; it must belong to this guild.
    if !db.owns(guild, save.system).await? {
        return ctx.reply_text(keys::TICKET_NOT_FOUND).await;
    }
    db.set_button_text(save.system, form.text.filter(|t| !t.trim().is_empty())).await?;
    redraw(&ctx, &db, Some(save.system)).await
}

#[handler]
async fn toggle_system(ctx: ComponentCtx, t: ToggleSystem, db: State<Db>) -> HandlerResult<Responded> {
    db.set_enabled(t.system, t.enable).await?;
    redraw(&ctx, &db, Some(t.system)).await
}

#[handler]
async fn add_system(ctx: ComponentCtx, _a: AddSystem, db: State<Db>) -> HandlerResult<Responded> {
    let guild = ctx.guild_id().ok_or_else(|| HandlerError::user(keys::COMMON_GUILD_ONLY))?;
    if db.ticket_systems(guild, 25).await?.systems.len() >= 25 {
        return ctx.reply_text(keys::TICKET_LIMIT).await;
    }
    let id = db.create_ticket_system(guild).await?;
    redraw(&ctx, &db, Some(id)).await                  // switch to the new one
}

/// Destructive: ask first, on a one-shot Route that expires (quality rule 3).
#[handler]
async fn ask_delete(ctx: ComponentCtx, a: AskDelete) -> HandlerResult<Responded> {
    let s = Strings::of(ctx.response_locale());
    ctx.update(render_confirm_delete(a.system, &s)).await
}

/// The handler every redraw goes through: load, then the one render function.
async fn redraw(ctx: &impl Ctx, db: &Db, selected: Option<u32>) -> HandlerResult<Responded> {
    let guild = ctx.guild_id().ok_or_else(|| HandlerError::user(keys::COMMON_GUILD_ONLY))?;
    let data = db.ticket_systems(guild, 25).await?;
    ctx.update(render_ticket_setup(&data, &Strings::of(ctx.response_locale()), selected)).await
}

// ---- autocomplete backed by storage, capped at 25 ------------------------------------
#[derive(Options, Debug)]
pub struct SendOptions {
    #[option(description = "Ticket system", autocomplete = system_suggest)]
    pub system: i64,
}

#[autocomplete]
async fn system_suggest(ctx: AutocompleteCtx, focused: Focused<String>, _p: Partial<SendOptions>, db: State<Db>)
    -> HandlerResult<Responded>
{
    let Some(guild) = ctx.guild_id() else { return Ok(ctx.respond([]).await?) };
    // Filter and cap in the query (LIMIT 25), not after loading every row.
    let rows = db.search_ticket_systems(guild, focused.as_str(), 25).await?;
    Ok(ctx.respond(rows.into_iter().map(|t| Choice::new(t.label, i64::from(t.id)))).await?)
}
```

`redraw` is called with a `&impl Ctx`; `update` is available on component and modal
contexts. Register every handler on the Module (`.add(pick_system())` …) and every
string in `locales/en-US.yaml`.

## 4. Budget helpers and cost [planned, Story 8.3]

```rust
let report = noctis::ui::cost(&msg, &limits);         // available today: CostReport
report.components;                                    // every depth, accessories included
report.text_chars;                                    // all Text Displays (CV2-04)

let budget = Budget::of(&fixed_parts, &limits);       // what is left beside the fixed parts
budget.components_left();                             // 40 - cost
budget.text_left();                                   // 4000 - text
budget.fits(&sample_row);                             // largest n such that n copies fit both
budget.fits_prefix(rows.iter());                      // how many rows from the front fit, in order
```

- Measure the message with its fixed parts in place (header, tab row, the pager row),
  then ask how many rows fit. Use a worst-case sample row for stable pages, or
  `fits_prefix` when rows differ a lot and you page by offset.
- Noctis never paginates, splits or truncates a message for you (Lenient mode only
  truncates over-long text, `limits-cheatsheet.md`). Over a Limit is a typed error with
  the path (`[CV2-03] components: limit at most 40, actual 41`).
- Cost cheatsheet: Container 1, Text Display 1, Separator 1, Section + 1 text + button
  = 3, Action Row + 5 buttons = 6, Action Row + 1 select = 2. Merge static text into one
  Text Display.

## 5. Attachments, mentions, user text, select freshness

- **Attachments** (FR-30): `ctx.render(card).await?` (or `Attachment::new(bytes, "png")`)
  gives an `Attachment`; add it to an `AttachmentSet` and put the returned
  `AttachmentRef` in a Media Gallery, Thumbnail or File; attach the set with
  `V2Message::attachments(set)` (`components-v2.md` §6). The same image used twice uploads
  once; on edit, unchanged names are kept without re-upload and unused ones dropped. Alt
  text is required for rendered images in strict mode.
- **Mentions**: messages ping nobody by default (`parse: []`, MSG-05) even though
  `<@id>` renders. Opt in per message with `.mentions(Mentions::none().users(Users::Only(ids)))`.
- **User text**: pass names, reasons and bios through `escape_markdown` /
  `escape_mentions` [planned, Story 8.2] before putting them in a Text Display.
- **Select freshness**: declare `select` on every select Route. Noctis draws a new
  nonce on each send, so after `ctx.update(..)` the client shows the defaults your render
  function declared (`default_channels`, `.default(true)`), not the user's previous
  local selection.
- **Unique ids** (CID-02): two components with the same Route and Payload in one
  message are an error. Give buttons that share a Route different Payloads (prev and
  next target different pages; per-row buttons carry the row id).

## 6. UI quality rulebook

1. **One primary action per View.** One Primary/Success button; everything else Secondary.
2. **Visible active state.** Disabled active tab, `default` on the current select
   option/value, state text next to toggles ("**Profiles** · enabled").
3. **Confirm destructive actions.** Danger button → small confirm screen ("Delete
   ticket system #3? This can't be undone.") with Cancel (Secondary) and Confirm (Danger)
   on a `by_ref, one_shot, ttl = "15m"` Route. Never delete on the first click.
4. **Ephemeral for single-user UI, public for shared content.** Settings, setup flows,
   errors, per-user panels → ephemeral (User Locale). Dashboards, cards, leaderboards
   others should see → public (Guild Locale).
5. **A way back or out.** Every interactive screen has Back, Cancel, a tab row, or a
   "Back to …" button that re-renders the parent. Drill-down state is just ids in
   Payloads, no navigation stack.
6. **Designed empty and error states.** "No ticket systems yet." in subtext, a disabled
   placeholder select; errors are one localized line (`ctx.reply_text(key)`), never a
   stack trace or a missing block.
7. **Hierarchy with Markdown, not components.** `#`/`##` title, `-#` subtext,
   `<t:…:R>` timestamps; merge static text into one Text Display.
8. **Short labels.** ≤ 34 chars with emoji; mobile wraps rows past ~3 labelled buttons.
9. **Images are read-only.** Wide visuals in Media Gallery; small icons in Thumbnail;
   never instructions inside an image; always alt text.
10. **Accent colour as state.** Neutral in progress, green complete, red error.

## 7. Best practices (schwi-style)

These come from the maintainer's production TypeScript bot (schwi-v2, on tescord) and
are how every Noctis bot should be written.

1. **One Module per feature, split by role.** `src/modules/<feature>/mod.rs` (the Module
   and its Routes, the feature's storage keys), `view.rs` (render functions),
   `handlers.rs` (slash Commands, component and modal handlers; schwi's `setup.ts` and
   `commands.ts`), `events.rs` (gateway events; schwi's `trigger.ts`). Module ids are
   path-like when nested (`Module::new("modules/ticket")`).
2. **`render_x(data, &strings, ids…) -> V2Message` is the single source of truth**,
   reused by the slash Command and every component and modal handler (§1).
3. **State only in typed Payload fields** of the module's own Routes: the selected
   entity id, the section (a `PayloadEnum` matched in the render function), the page,
   the step. Nothing per message, nothing in a global map.
4. **Handler flow: decode → validate/authorize → write → `ctx.update(render_x(..))`.**
   Payloads and select values are client input: check that the id belongs to the
   guild, clamp pages, parse strings; Route Guards (`owner = field`,
   `permissions = …`) run before the handler.
5. **Settings screens**: a Section per scalar setting (value in the text, "Edit"/"Set"
   accessory, Primary when unset), a caption plus a pre-filled select per channel/role
   setting, enable/disable toggles whose style encodes the action, "Add" and "Delete"
   rows at the bottom, separators between blocks (§3.4).
6. **Entity switcher**: a String Select of the guild's entities (≤ 25, `default` on the
   current one), shown only when there is more than one; its handler re-renders with
   the chosen id.
7. **Sections by `match`** on a `PayloadEnum` field (tabs, §3.1), never by string
   comparison.
8. **Prev/next disabled at the bounds**, on a Route whose Payload is the target page
   (§3.2); query one extra row to know whether a next page exists.
9. **Autocomplete backed by storage queries capped at 25** in the query itself (§3.4).
10. **Button → modal → re-render chains**: the button's Route and the modal's Route carry
    the same Payload; the button handler pre-fills the modal from storage; the submit
    handler saves and calls `ctx.update(render_x(..))` on the original message.
11. **Every user-visible string goes through the locale files** (`Strings::of(locale)`),
    modal titles and placeholders included; no "Todo localization" literals.
12. **One-line notices with `ctx.reply_text(key)`**: validation failures, "not found",
    limits reached. Ephemeral, localized, never a whole Container.

### Pitfalls from schwi-v2 (and what Noctis does instead)

| schwi-v2 did | Problem | In Noctis |
| --- | --- | --- |
| `if (tree.components.length > 40)` before falling back to a smaller editor | counts only top-level components; nested ones are missed, so the check passes while the real total is over 40 | `noctis::ui::cost` and `Budget` count every depth; the Responder validates before sending |
| free text (names, reasons) in custom-id data | breaks the 100-character limit at runtime and lets users forge it | typed Payload fields with a compile-time length proof; free text goes in storage or a `by_ref` Route |
| legacy Action Row-wrapped Text Inputs in modals (`type: 1, components: [TextInput]`) | deprecated shape; `label` on Text Input is deprecated | `#[derive(Modal)]` emits Label-wrapped inputs only |
| `data[0] as number`, `as any` on overrides | untyped data; a stale or forged id becomes a wrong value silently | typed Payload decode; a bad id is a typed error routed to the Expired/stale handler |
| copy-pasted rate-limit code in handlers | inconsistent and easy to forget | `rate_limit(..)` on `#[command]`/`#[handler]` (`modules-middleware-ratelimits.md`) |
| `flags: Ephemeral | IsComponentsV2` repeated in every handler, `deferUpdate` + `editReply` by hand | forgotten flags are 400s; a slow handler fails | `ctx.update(..)` / `ctx.respond(..)` set flags, ephemerality and deferral |
| `Math.random()` in select data to force fresh defaults | ad-hoc, wastes custom-id space | `select` Routes get a per-render nonce |
| next page disabled when `rows.length < 25` | one empty page too many when the last page is exactly full | query `per_page + 1` rows |

## 8. Decision table: which pattern?

| Situation | Pattern |
| --- | --- |
| Configure something once, in order (setup, onboarding, create-X) | step flow (§3.3) |
| Re-editable settings of one or more entities | settings screen (§3.4) |
| A general screen with distinct sections that don't fit one Container | tabs (§3.1), ≤ 5 |
| A homogeneous list that can exceed 40 components / 4000 characters | pagination (§3.2), inside the active tab if any |
| Pick one of many entities | String Select (≤ 25 per page) + prev/next |
| Dense read-only data (cards, charts, leaderboards) | a rendered Template image in a Media Gallery (`images.md`) |
| A one-line answer | `ctx.reply_text(key)` |
